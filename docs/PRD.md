# Suzuran Cloud PRD

> 产品需求文档 — 阐述功能存在的意义

## 愿景

构建一个 **AI 原生的多租户 SaaS 应用平台**：Agent 通过 Skill/MCP 契约直接开发并部署应用，应用运行在平台内、共享同一数据层。

## 为什么不是低代码

传统低代码平台（拖拽设计器、JSON schema 动态渲染、可视化工作流）的目标是降低开发门槛。但 Vibe Coding 的兴起让这个路径失效了：

- Agent 生成生产级代码的速度和质量已经超越拖拽设计器
- 拖拽产出的应用受限于平台 DSL，而 Agent 写出的代码可以任意复杂
- 低代码的"降低门槛"优势在 AI 时代不再稀缺

Suzuran Cloud 的转向是：**从"让人拖拽搭应用"变成"让 Agent 写代码跑应用"**。平台不再提供低代码编辑器，而是提供运行时 + 数据共享层 + 契约发布层。

## 核心能力

### 1. 多租户应用运行时

平台作为托管运行时，Agent 生成的应用部署在平台进程内运行。平台提供：
- 应用生命周期管理（创建、部署、启停、升级、销毁）
- 运行时隔离（应用间不能互相访问内存/文件系统）
- 请求路由（外部请求如何到达应用）
- 资源配额（CPU、内存、数据库连接）

### 2. MCP Server — 数据共享层

平台暴露严格的 MCP Server 契约，应用通过 MCP 读写共享数据：
- 基础数据：用户、组织、部门、权限
- 文件存储：上传/下载/预签名 URL
- 审计日志：操作记录查询
- 业务数据：跨应用的领域数据（通过平台定义的 schema 共享）

MCP 是 Agent 开发应用时唯一的数据访问通道。这保证了：
- 数据隔离的一致性（所有应用走同一个入口）
- 审计可追溯（每次读写都有记录）
- 跨应用共享（应用 A 的数据可以被应用 B 读取，前提是权限允许）

### 3. Skill/MCP 契约发布

平台提供严格契约（Schema、API 规范、MCP tool 定义），Agent 据此开发应用。契约包括：
- MCP tools：`org.getUsers()`、`file.upload()`、`data.query()` 等
- 应用 SDK：平台提供的运行时接口
- 数据模型：共享数据的 JSON Schema

契约一旦发布就稳定，Agent 不需要"猜测"平台行为。

### 4. OAuth-only 鉴权

平台自建 IdP，只支持 OAuth 登录：
- **WebAuthn**（Passkey）：生物识别 / 安全密钥，无密码注册登录
- **钉钉 OAuth**：企业用户一键登录，自动同步组织架构

密码登录被彻底移除。这是安全基线。

### 5. 跨应用数据共享

应用间共享数据分两层：
- **公共基础数据**：用户、组织、部门（通过 MCP 自然共享）
- **业务数据**：应用可以选择暴露部分数据给其他应用（通过平台定义的 schema 和权限控制）

这是 Suzuran Cloud 的核心差异化：应用不是孤岛，而是数据网络中的节点。

## 目标用户

- **Agent 开发者**：通过 Skill/MCP 契约开发应用的 AI Agent
- **平台运营方**（服务商）：管理租户、应用、资源配额
- **租户管理员**：管理自己组织内的应用、用户、数据
- **终端用户**：使用平台上的各种应用

## 非目标

- ❌ 低代码拖拽设计器
- ❌ 可视化工作流编辑器
- ❌ JSON schema 动态表单渲染
- ❌ 报表设计器
- ❌ 密码登录
- ❌ 集成第三方 IdP（Keycloak/Authentik）

## 成功指标

- Agent 能在 10 分钟内通过 Skill/MCP 契约开发并部署一个应用
- 应用间数据共享延迟 < 50ms（同地域）
- 平台能托管 100+ 应用，每个应用 1000+ 并发用户
- OAuth 登录成功率 > 99.9%

## 当前状态（2026-08-04）

项目已从低代码平台成功转型为 AI 原生应用平台，**Agent 接入能力已就绪**。

**已完成的基座能力**：
- ✅ 多租户架构（org/user/bond/dept + org_id 隔离 + 审计日志）
- ✅ OAuth IdP（WebAuthn 无密码登录 + 钉钉 OAuth + RS256 JWT）
- ✅ MCP Server（23 个 tools + 9 个 prompts + 4 个 schema resources，完整的数据共享层）
- ✅ 应用运行时（Docker 沙箱隔离 + 生命周期管理 + OAUTH_TOKEN 自动注入）
- ✅ @suzuran/sdk v1.0.0（零依赖 Node.js SDK，一行代码接入）
- ✅ Skill/MCP 契约文档 v1.0.0（含 hello-world 示例应用）
- ✅ 三端门户前端（provider/tenant/user + 应用启动台）

**Agent 现在可以**：
1. 通过 `@suzuran/sdk` 创建应用（`createApp()`）
2. 自动获取 OAuth token（从环境变量 `OAUTH_TOKEN`）
3. 调用 23 个 MCP tools（组织/用户/部门/文件/审计/数据查询）
4. 部署到容器化沙箱（平台自动注入鉴权信息）
5. 通过反向代理接收外部请求

**当前价值受限的原因**：
- 平台提供了完整的基座（认证、组织、文件、审计、数据共享），但还没有真正的业务应用被 Agent 开发出来并运行在上面
- 终端用户登录后能看到应用启动台，但点进去的应用需要 Agent 先开发部署
- 跨应用数据共享是潜力，不是现成产品

**真正能立即受益的客户画像**：有 IT 团队的企业，他们让 AI Agent（通过 MCP 契约）快速开发内部工具，利用平台已有的组织架构、文件存储、审计能力，省去从零搭基座的成本。

**下一步**：制定架构方案和分阶段实施计划。
